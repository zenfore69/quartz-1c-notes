**1. Клиент-серверная архитектура 1С**

**Общая схема**

Современные приложения 1С работают по **клиент-серверной архитектуре**, которая состоит из **трёх компонентов**:

1.  **Клиент 1С**

    - Приложение, с которым работает пользователь

    - Пример: сеанс в режиме *«1С:Предприятие»*

2.  **Сервер 1С**

    - Отдельная программа

    - Принимает запросы от клиентов

    - Обрабатывает бизнес-логику

    - Передаёт запросы в СУБД и возвращает результат клиенту

3.  **СУБД (Система управления базами данных)**

    - Отвечает за хранение и обработку данных

    - Работает с таблицами

    - Выполняет SQL-запросы

    - Примеры: MS SQL Server, PostgreSQL

**Важный вывод**

🧠 **Все данные хранятся именно в базе данных**, а не:

- не на клиенте

- не на сервере 1С

Это ключевой момент для понимания запросов.

**2. Что такое база данных (упрощённо)**

Для разработчика 1С базу данных можно воспринимать как:

- файл с большим объёмом данных

- данные хранятся **в таблицах**

- таблицы **связаны между собой**

**Примеры таблиц:**

- Справочник *Контрагенты* → таблица контрагентов

- Документ *Чек* → таблица чеков

- Справочник *Номенклатура* → таблица номенклатуры

⚠️ В реальности устройство БД сложнее, но **для запросов этого представления достаточно**.

**3. Две модели доступа к данным в 1С**

В 1С есть **две принципиально разные модели** работы с данными:

**3.1 Объектная модель доступа к данным**

**Суть**

- Работа идёт **через объекты встроенного языка**

- У объектов есть **методы**, которые:

  - читают данные

  - записывают данные

  - удаляют данные

**Примеры:**

- Справочники.Номенклатура.НайтиПоРеквизиту()

- Документы.ЗаказКлиента.НайтиПоНомеру()

- РегистрыСведений.ЦеныНоменклатуры.ПолучитьПоследнее()

- ОбъектДокумента.Записать()

**Как это работает**

- Вызываем метод

- Платформа сама формирует запрос к базе

- Мы **не видим SQL/запрос**, он скрыт

✅ Просто

❌ Мало гибкости

**3.2 Табличная модель доступа к данным (запросы)**

**Суть**

- Мы **работаем напрямую с таблицами**

- Явно указываем:

  - из каких таблиц брать данные

  - какие поля

  - какие условия

  - группировки, сортировки, итоги

**Важно**

🧠 **Один объект конфигурации ≠ одна таблица**

**Примеры:**

- Справочник *Контрагенты*:

  - основная таблица

  - таблица контактной информации

  - таблица дополнительных реквизитов

- Справочник *Валюты* (без табличных частей):

  - одна таблица

**4. Почему объектной модели недостаточно**

**Ограничения объектной модели**

**1️⃣ Нельзя получить данные сразу из нескольких таблиц**

Например:

- Номенклатура + Цены номенклатуры

- Валюты + Курсы валют

Нужно вызывать **несколько объектов**, что неудобно.

**2️⃣ Ограниченные фильтры**

Доступно:

- Найти по коду

- Найти по наименованию

- Найти по реквизиту

❌ Нельзя:

- сложные условия

- списки значений

- комбинированные фильтры

**3️⃣ Нет агрегации**

Нельзя:

- группировать

- считать итоги

- агрегировать данные

**Главный недостаток --- избыточное чтение**

**Пример**

Ссылка = Документы.ЗаказКлиента.НайтиПоНомеру(\...);

Объект = Ссылка.ПолучитьОбъект();

Что происходит:

- читается **весь документ**

- читаются **все табличные части**

- читаются **все вложенные файлы (ХранилищаЗначения)**

⚠️ Даже если нужен только номер или контрагент.

**Почему так сделано**

Платформа предполагает, что:

- объект будет **изменён**

- значит данные лучше считать сразу целиком

❌ Это плохо для производительности

❌ Лишний трафик

❌ Долгое выполнение

**5. Преимущества табличной модели (запросов)**

✅ Получаем **только нужные поля**

✅ Работаем сразу с несколькими таблицами

✅ Фильтрация, группировка, сортировка

✅ Нет избыточного чтения

✅ Лучше масштабируется

**6. Что такое запрос в 1С**

**Определение**

**Запрос** --- это инструкция для платформы 1С, описанная на **языке запросов 1С**, которая определяет:

- из каких таблиц читать данные

- какие поля

- какие условия

- как группировать и сортировать

- какие итоги считать

⚠️ В 1С **запросы ТОЛЬКО НА ЧТЕНИЕ**

- нельзя изменять данные

- нельзя удалять данные

- для этого используется объектная модель

**7. Как выполняется запрос**

Цепочка выполнения:

1.  1С формирует запрос

2.  Платформа **транслирует** его в SQL

3.  SQL выполняется в СУБД

4.  Результат возвращается серверу 1С

5.  Сервер 1С возвращает данные клиенту

🧠 Даже объектные методы внутри используют запросы --- просто они скрыты.

**8. Структура текста запроса**

Запрос состоит из **секций**, каждая начинается с ключевого слова:

**Основные секции:**

1.  **ВЫБРАТЬ** --- какие поля получить

2.  **ИЗ** --- из каких таблиц

3.  **ГДЕ** --- условия фильтрации

4.  **СГРУППИРОВАТЬ ПО** --- группировка

5.  **УПОРЯДОЧИТЬ ПО** --- сортировка

6.  **ИТОГИ ПО** --- расчёт итогов

⚠️ Порядок секций **строго фиксирован**

**9. Конструктор запросов**

**Что это**

Визуальный инструмент, который:

- помогает формировать текст запроса

- автоматически следит за синтаксисом

- снижает количество ошибок

**Где доступен**

- В **Конфигураторе**

- В **Консоли запросов**

🧠 Можно:

- сначала собрать запрос визуально

- потом доработать текст вручную

**10. Консоль запросов**

**Назначение**

Инструмент для:

- написания запросов

- быстрого выполнения

- анализа результата

- отладки

**Возможности**

- список запросов

- сохранение в файл (.mcr)

- параметры

- время выполнения

- быстрый повторный запуск

**Практика**

Часто используется:

- при обучении

- при отладке

- при выполнении домашних заданий

**11. Важные практические нюансы**

⚠️ Запятая в секции ВЫБРАТЬ

- после последнего поля **НЕ ставится**

⚠️ Проверка корректности запроса

- если запрос открывается в конструкторе --- синтаксис корректный

🧠 Лучше писать запросы:

- сначала через конструктор

- затем при необходимости править вручную

**Краткий итог**

- В 1С есть **две модели доступа к данным**

- Для чтения данных **предпочтительны запросы**

- Запросы работают с таблицами

- Объект конфигурации может соответствовать нескольким таблицам

- Запросы дают гибкость и производительность

- Консоль запросов --- основной инструмент для практики

**Запросы в 1С --- секция ГДЕ, условия и параметры**

**12. Зачем нужна секция ГДЕ**

На практике почти никогда не требуется:

- читать **все** данные таблицы

- без фильтрации

Чаще нужно:

- выбрать только элементы (без групп)

- получить данные по конкретному значению

- отобрать записи по дате, признаку, статусу и т.д.

👉 Для этого используется **секция ГДЕ**.

**13. Общая структура запроса с условием**

Простейший запрос с фильтрацией выглядит так:

ВЫБРАТЬ

\...

ИЗ

\...

ГДЕ

\<условие\>

🧠 **Секция ГДЕ всегда идёт после секции ИЗ**

**14. Пример задачи**

**Выбрать номенклатуру без групп**

**Анализ структуры данных**

В справочнике *Номенклатура*:

- элементы и группы хранятся в одной таблице

- различие определяется реквизитом **ЭтоГруппа**

Значения поля:

- Истина (Да) --- группа

- Ложь (Нет) --- элемент

**15. Реализация условия через конструктор запроса**

**Шаги в конструкторе:**

1.  Выбираем таблицу **Справочник.Номенклатура**

2.  Добавляем нужные поля (Код, Наименование, Артикул и т.д.)

3.  Переходим на закладку **Условия**

4.  Выбираем поле **ЭтоГруппа**

5.  Формируем условие:

6.  Номенклатура.ЭтоГруппа = ЛОЖЬ

7.  

📌 В результате в запрос добавляется секция ГДЕ.

**16. Формы задания условия**

В конструкторе есть **два режима задания условий**:

**16.1 Стандартный (рекомендуемый)**

Условие разбито на части:

- Левое значение (поле)

- Вид сравнения

- Правое значение / параметр

Пример:

ЭтоГруппа = ЛОЖЬ

**16.2 Произвольное условие**

Флаг **«Произвольное»**:

- позволяет редактировать условие как текст

- удобно для сложных выражений

⚠️ Минус: легко допустить синтаксическую ошибку

✅ Использовать, когда стандартного режима недостаточно

**17. Параметры в секции ГДЕ**

**Зачем нужны параметры**

Параметры позволяют:

- не «зашивать» значения в текст запроса

- передавать значения из кода

- переиспользовать запрос

**Пример условия с параметром:**

Номенклатура.Артикул = &Артикул

🔹 &Артикул --- параметр запроса

**18. Установка параметров в коде**

После формирования текста запроса:

Запрос.УстановитьПараметр(\"Артикул\", Артикул);

⚠️ Важно:

- имя параметра **без &**

- имя должно **точно совпадать**

- регистр символов имеет значение

**19. Проверка результата запроса**

После выполнения запроса:

- результатом **всегда является таблица**

- количество строк и колонок зависит от запроса

Если:

- таблица пустая → данные не найдены

- таблица содержит строки → данные найдены

🧠 Даже если ожидается одна строка --- результат всё равно таблица.

**20. Частая ошибка новичков**

❌ Ошибка мышления:

«Я ищу один элемент --- значит результат будет один объект»

✅ На самом деле:

- запрос **всегда возвращает таблицу**

- даже одна строка --- это таблица из одной строки

**21. Логические операции в секции ГДЕ**

Можно использовать:

- И

- ИЛИ

- НЕ

**Пример:**

ГДЕ

Номенклатура.ЭтоГруппа = ЛОЖЬ

И Номенклатура.ВидНоменклатуры = &Вид

🧠 При сложных условиях лучше использовать скобки.

**22. Итог по секции ГДЕ**

**Что важно запомнить:**

- секция ГДЕ фильтрует строки

- условия можно задавать через параметры

- результат запроса --- таблица

- параметры делают запросы универсальными

- конструктор снижает риск ошибок

**Короткая выжимка (для повторения)**

- **ГДЕ** --- фильтрация данных

- ЭтоГруппа = ЛОЖЬ → только элементы

- &Параметр → значение из кода

- Запрос всегда возвращает таблицу

- Параметры устанавливаются через УстановитьПараметр

**Запросы в 1С --- параметры, виды сравнений, сложные условия**

**23. Параметры запроса --- углубление**

**Что такое параметр**

**Параметр** --- это именованная переменная внутри текста запроса, значение которой:

- задаётся **перед выполнением**

- может меняться без изменения текста запроса

Обозначается:

&ИмяПараметра

**24. Почему параметры --- это must-have**

Использование параметров:

- ✅ повышает читаемость запроса

- ✅ позволяет переиспользовать запрос

- ✅ защищает от ошибок и «зашитых значений»

- ✅ упрощает отладку в консоли запросов

❌ Плохая практика:

ГДЕ Номенклатура.Артикул =\"SJ-12\"

✅ Правильно:

ГДЕ Номенклатура.Артикул = &Артикул

**25. Типы сравнений в секции ГДЕ**

В языке запросов 1С доступны следующие виды сравнений.

**25.1 Равенство и неравенство**

=

\<\>

Примеры:

Цена = &Цена

Количество\<\> 0

**25.2 Сравнение чисел и дат**

\>

\<

\>=

\<=

Примеры:

Дата \> &ДатаНачала

Количество \>= 10

⚠️ Работает и для чисел, и для дат

**25.3 Оператор МЕЖДУ**

Используется для диапазонов.

ГДЕ

Документ.Дата МЕЖДУ &ДатаНачала И &ДатаОкончания

🧠 Эквивалент:

Дата \>= &ДатаНачала

И Дата \<= &ДатаОкончания

**25.4 Проверка на NULL / Пустые значения**

В 1С используется:

ЕСТЬNULL

Пример:

ГДЕ

Заказ.Склад ЕСТЬNULL

🧠 Актуально для:

- необязательных реквизитов

- связей, которые могут отсутствовать

**25.5 Оператор В**

Используется для проверки вхождения в список.

ГДЕ

ВидНоменклатуры В (&СписокВидов)

📌 &СписокВидов --- массив или список значений

**26. Логические операторы**

В секции ГДЕ можно комбинировать условия:

- И

- ИЛИ

- НЕ

**Пример сложного условия**

ГДЕ

Номенклатура.ЭтоГруппа = ЛОЖЬ

И (

Номенклатура.ВидНоменклатуры = &Вид

ИЛИ Номенклатура.Артикул = &Артикул

)

⚠️ **Скобки критически важны**, иначе логика изменится.

**27. Частая логическая ошибка**

❌ Ошибка:

А И Б ИЛИ В

🧠 Как интерпретирует платформа:

(А И Б) ИЛИ В

Если нужна другая логика --- **всегда ставь скобки**.

**28. Несколько условий по одному полю**

Допустимо и часто используется:

ГДЕ

Цена \> 0

И Цена \<= &МаксимальнаяЦена

**29. Использование параметров в консоли запросов**

**Как это работает**

Если в тексте запроса есть параметр:

&Артикул

То:

- консоль автоматически покажет список параметров

- ты можешь задать значения вручную

- выполнить запрос несколько раз с разными значениями

🧠 **Очень удобно для отладки**

**30. Параметры и типы данных**

⚠️ Важно:

- параметр **должен быть того же типа**, что и поле

- если поле --- ссылка, параметр тоже должен быть ссылкой

Пример:

Номенклатура.ВидНоменклатуры = &Вид

Значение &Вид:

- ❌ строка

- ✅ ссылка на элемент справочника

**31. Результат запроса с условиями**

Независимо от условий:

- результат → **таблица значений**

- может быть:

  - 0 строк

  - 1 строка

  - много строк

❗ Никогда не объект и не ссылка напрямую.

**32. Ключевые грабли (⚠️ обязательно запомнить)**

⚠️ Параметр без установки → ошибка

⚠️ Неверный тип параметра → пустой результат

⚠️ Отсутствие скобок → неверная логика

⚠️ Сравнение ссылок со строками → не работает

**33. Промежуточный итог**

Мы разобрали:

- секцию **ГДЕ**

- параметры запросов

- виды сравнений

- сложные логические условия

- работу с параметрами в консоли

🧠 Это **фундамент**, без которого дальше (соединения, группировки) будет очень тяжело.

**Запросы в 1С --- секция УПОРЯДОЧИТЬ ПО (сортировка данных)**

**34. Зачем нужна сортировка в запросах**

По умолчанию:

- **порядок строк в результате запроса не гарантирован**

- нельзя рассчитывать, что данные придут «как в справочнике»

Если нужен:

- алфавитный порядок

- сортировка по дате

- сначала новые, потом старые

- сначала большие значения, потом маленькие

👉 используется секция **УПОРЯДОЧИТЬ ПО**

**35. Общая структура сортировки**

ВЫБРАТЬ

\...

ИЗ

\...

ГДЕ

\...

УПОРЯДОЧИТЬ ПО

\<поле\>

🧠 Секция **УПОРЯДОЧИТЬ ПО**:

- всегда идёт **после ГДЕ**

- может отсутствовать

**36. Сортировка по одному полю**

**Пример**

Отсортировать номенклатуру по наименованию:

УПОРЯДОЧИТЬ ПО

Номенклатура.Наименование

📌 По умолчанию используется **возрастающий порядок**

**37. Направление сортировки**

Можно явно указать направление:

- **ВОЗРАСТАНИЕ**

- **УБЫВАНИЕ**

**Примеры**

УПОРЯДОЧИТЬ ПО

Дата УБЫВАНИЕ

УПОРЯДОЧИТЬ ПО

Цена ВОЗРАСТАНИЕ

🧠 Если направление не указано --- считается **ВОЗРАСТАНИЕ**

**38. Сортировка по нескольким полям**

Очень частый кейс.

**Пример**

Сначала по виду номенклатуры, потом по наименованию:

УПОРЯДОЧИТЬ ПО

**44. Зачем нужна группировка**

Группировка используется, когда нужно:

- получить **итоги** по данным

- объединить строки по общему признаку

- перейти от «детальных данных» к **аналитике**

**Типовые задачи:**

- сумма продаж по номенклатуре

- количество документов по контрагенту

- обороты по складам

- итоги по месяцам

👉 Для этого применяется секция **СГРУППИРОВАТЬ ПО**.

**51. Использование КОЛИЧЕСТВО(\*)**

- считает **количество строк** в группе

- влияет на исходные данные

**(будет дальше) ИМЕЮЩИЕ**

- фильтрация **после группировки**

- влияет на группы

🧠 Это разные этапы выполнения запроса.

**54. Итог по секции СГРУППИРОВАТЬ ПО**

- используется с агрегатными функциями

- каждая строка результата = одна группа

- все поля ВЫБРАТЬ → либо агрегат, либо в группировке

- можно группировать по нескольким полям

- отлично сочетается с разыменованием

**Запросы в 1С --- секция ИМЕЮЩИЕ (фильтрация после группировки)**

**56. Зачем нужна секция ИМЕЮЩИЕ**

Очень частая задача:

- получить **не все группы**,

- а только те, которые удовлетворяют условию **по итогам**.

Примеры:

- товары, по которым сумма продаж \> 100 000

- контрагенты с количеством документов \> 5

- склады с отрицательными остатками

👉 Для этого используется **ИМЕЮЩИЕ**.

  ГДЕ          до группировки          к строкам

  ИМЕЮЩИЕ      после группировки       к группам
  -------------------------------------------------------------

**83. Что такое регистры в 1С (коротко)**

**Регистры** --- это специализированные объекты конфигурации, предназначенные:

- для хранения **аналитических данных**

- для быстрого получения итогов

- для расчётов (остатки, обороты, значения)

🧠 В отличие от документов и справочников, регистры:

- почти всегда читаются **через запросы**

- редко читаются объектной моделью

**84. Виды регистров**

В рамках запросов нас интересуют два основных вида:

**84.1 Регистры накопления**

Используются для:

- количественно-суммового учёта

- остатков

- оборотов

📌 Примеры:

- Остатки товаров

- Обороты продаж

- Движения денежных средств

**84.2 Регистры сведений**

Используются для:

- хранения значений параметров

- цен, курсов, настроек

- периодических и непериодических данных

📌 Примеры:

- Цены номенклатуры

- Курсы валют

- Настройки пользователей

**Запросы в 1С --- соединения таблиц (JOIN)**

**100. Зачем нужны соединения таблиц**

Соединения используются, когда данные:

- находятся **в разных таблицах**

- логически связаны между собой

**Типовые задачи:**

- номенклатура + цены

- документ + табличная часть

- регистр + справочник

- контрагент + договор

👉 Всё это решается через **соединения таблиц**.

**101. Общий принцип соединения**

🧠 **Соединение** --- это объединение строк двух таблиц по условию.

Обычно:

- условие соединения --- **равенство ссылок**

- одна таблица «ссылается» на другую

**102. Как выглядят соединения в языке запросов 1С**

В 1С используется ключевое слово:

СОЕДИНЕНИЕ

Общая структура:

ИЗ

Таблица1 КАК Т1

\<ТИПСОЕДИНЕНИЯ\> Таблица2 КАК Т2

ПО\<условиесоединения\>

**103. Основные типы соединений**

В 1С используются те же логические типы, что и в SQL:

**103.1 ВНУТРЕННЕЕ СОЕДИНЕНИЕ**

ВНУТРЕННЕЕ СОЕДИНЕНИЕ

- возвращает строки, **которые есть в обеих таблицах**

- самый часто используемый тип

**103.2 ЛЕВОЕ СОЕДИНЕНИЕ**

ЛЕВОЕ СОЕДИНЕНИЕ

- возвращает **все строки из левой таблицы**

- из правой --- только если есть совпадение

- если совпадения нет → NULL

**103.3 ПРАВОЕ СОЕДИНЕНИЕ**

ПРАВОЕ СОЕДИНЕНИЕ

- используется редко

- аналогично левому, но наоборот

📌 На практике почти всегда используют **левое**, а не правое.

**104. Пример ВНУТРЕННЕГО СОЕДИНЕНИЯ**

**Задача**

Получить номенклатуру **с ценами**, только если цена есть.

ВЫБРАТЬ

Номенклатура.Ссылка,

Номенклатура.Наименование,

Цены.Цена

ИЗ

Справочник.Номенклатура КАК Номенклатура

ВНУТРЕННЕЕ СОЕДИНЕНИЕ

РегистрСведений.ЦеныНоменклатуры КАК Цены

ПО Номенклатура.Ссылка = Цены.Номенклатура

🧠 Если для товара нет цены --- строка **не попадёт в результат**.

**105. Пример ЛЕВОГО СОЕДИНЕНИЯ**

**Та же задача, но:**

👉 показать **всю номенклатуру**, даже без цены.

ЛЕВОЕ СОЕДИНЕНИЕ

ИЗ

Справочник.Номенклатура КАК Номенклатура

ЛЕВОЕ СОЕДИНЕНИЕ

РегистрСведений.ЦеныНоменклатуры КАК Цены

ПО Номенклатура.Ссылка = Цены.Номенклатура

📌 Если цены нет:

- Цены.Цена = NULL

**106. Где писать условия: ПО или ГДЕ (⚠️ ВАЖНО)**

**Условие соединения --- ПО**

ПО Номенклатура.Ссылка = Цены.Номенклатура

**Условия фильтрации --- ГДЕ**

❌ Ошибка:

ГДЕ Номенклатура.Ссылка = Цены.Номенклатура

🧠 Это ломает логику левого соединения.

**107. Частая ошибка с ЛЕВЫМ СОЕДИНЕНИЕМ**

❌ Ошибка:

Что происходит:

✅ Правильно:

**Запросы в 1С --- вложенные запросы (подзапросы)**

**115. Что такое вложенный запрос**

**Вложенный запрос** --- это запрос, который используется **внутри другого запроса**.

Он может находиться:

- в секции **ИЗ**

- в секции **ГДЕ**

- реже --- в секции **ВЫБРАТЬ**

🧠 По сути:

сначала выполняется внутренний запрос,

затем его результат используется внешним запросом.

**116. Зачем нужны вложенные запросы**

Вложенные запросы используют, когда:

- данные нужно **предварительно подготовить**

- требуется сложная фильтрация

- нельзя или неудобно решить задачу JOIN'ом

- нужно работать с агрегированными данными

**Типовые задачи:**

- отбор по списку значений

- фильтрация по результату агрегатного запроса

- многоэтапная аналитика

**129. Почему оптимизация запросов критична**

  - фоновые задания
