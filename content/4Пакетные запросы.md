**Пакетные запросы. Временные таблицы. Работа с запросами в коде**

**1. Краткое напоминание контекста (откуда мы пришли)**

К этому моменту мы уже умеем:

- писать простые и сложные запросы

- работать с физическими и виртуальными таблицами

- использовать параметры виртуальных таблиц

- соединять таблицы (JOIN)

- объединять результаты (UNION)

- применять вложенные запросы

📌 **Следующий шаг --- оптимизация и архитектура запросов**, а не просто «чтобы работало».

**2. Зачем вообще нужны пакетные запросы**

Типичная ситуация:

- нужно получить **несколько разных наборов данных**

- данные **не объединяются** в один результат

- но используются **в рамках одной логической операции**

Примеры:

- список контрагентов + список номенклатуры

- остатки + цены

- справочники + движения

- вспомогательные данные для расчётов

**3. Как работает обычный запрос (важно понять)**

Архитектура 1С:

- клиент

- сервер 1С

- СУБД

🧠 **Запрос --- это серверный механизм.**

Алгоритм:

1.  сервер 1С формирует SQL

2.  отправляет его в СУБД

3.  СУБД выполняет

4.  результат возвращается на сервер 1С

📌 **Каждый запрос = отдельный сетевой/процессный обмен**.

**4. В чём проблема большого количества запросов**

Если выполнить:

- 1 запрос → 1 обмен

- 5 запросов → 5 обменов

- 20 запросов → 20 обменов

⚠️ Даже если всё на одном сервере --- накладные расходы есть всегда.

**5. Идея пакетного запроса**

**Пакетный запрос** --- это:

- один объект Запрос

- один вызов к СУБД

- **несколько запросов внутри**

- **несколько результатов на выходе**

📌 Все запросы выполняются **за один проход**.

**6. Аналогия «поход в магазин» 🛒**

Обычные запросы:

- сходил за апельсинами

- вернулся

- сходил за бананами

- вернулся

- сходил за картошкой

Пакетный запрос:

- один поход

- купил всё сразу

🧠 **Меньше походов --- быстрее результат**.

**7. Что такое пакетный запрос формально**

📌 **Пакетный запрос --- это текст запроса, состоящий из нескольких запросов, разделённых ;**

Пример структуры:

Запрос 1;

Запрос 2;

Запрос 3;

Каждый запрос:

- выполняется последовательно

- имеет **порядковый номер**

- может возвращать результат

**8. Что возвращает пакетный запрос**

В результате выполнения:

- возвращается **несколько результатов**

- каждый результат соответствует **своему запросу пакета**

- к ним можно обращаться **по индексу**

📌 Это не один набор данных, а **несколько**.

**9. Пакетные запросы в конструкторе**

В конструкторе запроса есть специальная вкладка:

**🔹 «Пакет запросов»**

Здесь:

- каждый запрос --- отдельная вкладка

- можно:

  - добавлять

  - менять порядок

  - удалять

🧠 По этой вкладке сразу видно архитектуру запроса.

**10. Типы запросов в пакете**

В пакетном запросе **каждый запрос имеет тип**:

1️⃣ Выборка данных

2️⃣ Создание временной таблицы

3️⃣ Уничтожение временной таблицы

📌 Тип задаётся на вкладке **«Дополнительно»**.

**11. Тип 1 --- Выборка данных**

Классический запрос:

- возвращает результат

- отображается в консоли

- используется для:

  - анализа

  - обработки

  - вывода

📌 Таких запросов в пакете может быть несколько.

**12. Тип 2 --- Создание временной таблицы**

Запрос:

- **не для вывода**

- а для сохранения результата

- в **временную таблицу**

Ключевая конструкция:

ПОМЕСТИТЬ ИмяТаблицы

📌 Имя --- обычный идентификатор:

- без пробелов

- без спецсимволов

- уникальное в рамках пакета

**13. Что такое временная таблица**

**Временная таблица** --- это:

- таблица, созданная **на время выполнения запроса**

- хранит промежуточный результат

- доступна:

  - в последующих запросах пакета

- недоступна:

  - вне этого запроса

🧠 По смыслу --- «переменная», но **табличная**.

**14. Где живёт временная таблица**

По умолчанию:

- создаётся **в оперативной памяти СУБД**

При необходимости:

- может быть выгружена на диск

- в служебную БД (tempdb в SQL Server)

📌 Это делает СУБД автоматически.

**15. Когда появляются временные таблицы в конструкторе**

Важно:

- в **первом запросе пакета**

> временных таблиц ещё **нет**

- во **втором и далее**

> они появляются в отдельной группе:
>
> **«Временные таблицы»**

🧠 Это отражает реальный порядок выполнения.

**16. Тип 3 --- Уничтожение временной таблицы**

Если временная таблица:

- больше не нужна

- большая

- занимает память

➡️ её можно **уничтожить вручную**.

Тип запроса:

- **«Уничтожение временной таблицы»**

Ключевая конструкция:

УНИЧТОЖИТЬ ИмяТаблицы

**17. Время жизни временной таблицы**

По умолчанию:

- живёт **до конца пакетного запроса**

Можно:

- уничтожить раньше

- освободить ресурсы

- избежать лишнего потребления памяти

📌 Особенно важно для «тяжёлых» таблиц.

**18. Важное ограничение ⚠️**

❗ **Имена временных таблиц в одном пакете не могут повторяться**

Если повторить:

- запрос не выполнится

- будет ошибка «временная таблица уже существует»

**19. Когда временные таблицы --- хорошая идея**

✅ Когда:

- запрос слишком сложный

- много JOIN

- есть виртуальные таблицы

- логика многоэтапная

- нужен читаемый код

🧠 Это **архитурный инструмент**, а не трюк.

**20. Когда временные таблицы --- плохая идея ⚠️**

❌ Когда:

- туда попадают сотни тысяч / миллионы строк

- нет фильтрации

- таблица «на всякий случай»

- используется вместо нормальной логики

📌 Рекомендация:

стараться, чтобы ВТ были до \~10 000 строк

**21. Главный плюс пакетных запросов**

- меньше обращений к СУБД

- выше производительность

- лучше масштабируемость

- проще сопровождение

**Пакетные запросы и временные таблицы --- практические приёмы**

**23. Зачем на практике нужны временные таблицы**

На практике временные таблицы используют, когда:

- запрос становится **слишком сложным**

- много JOIN + виртуальные таблицы

- нужны **промежуточные итоги**

- данные используются **несколько раз**

- запрос трудно читать и отлаживать

🧠 ВТ --- это способ **разбить один сложный запрос на шаги**.

**24. Классический кейс: «остатки + цены + отбор»**

**Задача**

- получить остатки товаров

- добавить актуальные цены

- отобрать только нужные позиции

Без ВТ:

- длинный запрос

- много JOIN

- сложная оптимизация

С ВТ:

- шаги понятны

- проще отладка

- выше производительность

**25. Шаг 1 --- получаем остатки во временную таблицу**

ВЫБРАТЬ

Остатки.Номенклатура,

СУММА(Остатки.КоличествоОстаток) КАК Остаток

ПОМЕСТИТЬ ВТ_Остатки

ИЗ

РегистрНакопления.ТоварыНаСкладах.Остатки(&Дата)

КАК Остатки

СГРУППИРОВАТЬ ПО

Остатки.Номенклатура

📌 Здесь:

- считаем только то, что нужно

- сразу агрегируем

- минимальный объём данных

**26. Что мы получили на выходе**

ВТ_Остатки:

- одна строка = одна номенклатура

- уже есть итог

- нет лишних колонок

- нет лишних строк

🧠 Это **идеальный набор данных для дальнейшей работы**.

**27. Шаг 2 --- используем временную таблицу**

Теперь можно:

- соединять со справочниками

- соединять с регистрами сведений

- фильтровать

- сортировать

ВЫБРАТЬ

Ост.Номенклатура,

Ост.Остаток,

Цены.Цена

ИЗ

ВТ_Остатки КАК Ост

ЛЕВОЕ СОЕДИНЕНИЕ

РегистрСведений.ЦеныНоменклатуры.СрезПоследних(&Дата)

КАК Цены

ПО Ост.Номенклатура = Цены.Номенклатура

📌 Запрос стал:

- короче

- понятнее

- легче для оптимизации

**28. Почему это быстрее, чем один большой запрос**

🧠 Причины:

1️⃣ Остатки считаются **один раз**

2️⃣ Нет повторных виртуальных таблиц

3️⃣ JOIN идёт по **маленькой ВТ**

4️⃣ Меньше данных → быстрее соединение

📌 Особенно критично на больших базах.

**29. Частая ошибка: тащить всё во временную таблицу ⚠️**

❌ Плохо:

- ВТ на 500 000 строк

- без фильтрации

- «потом разберусь»

**Почему плохо**

- память

- tempdb

- тормоза

- блокировки

**✅ Хорошо**

- ВТ --- **результат отбора или агрегации**

- 1--2 ключевые колонки

- минимум строк

**30. Несколько временных таблиц в пакете**

Допустимо и нормально:

ВТ_Остатки

ВТ_Цены

ВТ_Контрагенты

🧠 Главное:

- понятные имена

- логический порядок

- не злоупотреблять

**31. Порядок выполнения пакетного запроса**

❗ Очень важно понимать:

- запросы выполняются **строго сверху вниз**

- временная таблица доступна

> **только после её создания**

- в первом запросе ВТ нет

📌 Ошибка порядка = ошибка выполнения.

**32. Типовая ошибка с порядком ⚠️**

❌ Ошибка:

- использовать ВТ

- до запроса с ПОМЕСТИТЬ

📌 Конструктор это **не всегда подсвечивает**.

**33. Уничтожение временных таблиц --- когда нужно**

Обычно:

- не обязательно

- ВТ уничтожаются автоматически

Но **желательно уничтожать**, если:

- ВТ большая

- ВТ больше не нужна

- пакет длинный

УНИЧТОЖИТЬ ВТ_Остатки

🧠 Это хорошая практика для тяжёлых запросов.

**Работа с запросами в коде 1С**

**38. Объект Запрос --- базовая точка входа**

В коде 1С запрос всегда начинается с объекта:

Запрос = Новый Запрос;

🧠 Объект Запрос:

- хранит текст запроса

- хранит параметры

- управляет выполнением

- возвращает результат

**39. Установка текста запроса**

**Способ 1 --- напрямую (простой и частый)**

Запрос.Текст =

\"ВЫБРАТЬ

\| Номенклатура,

\| Цена

\|ИЗ

\| РегистрСведений.ЦеныНоменклатуры\";

📌 Символ \|:

- просто перенос строки

- улучшает читаемость

- не влияет на выполнение

**Способ 2 --- через конструктор (самый безопасный)**

- запрос собирается в конструкторе

- копируется в код

- минимизирует синтаксические ошибки

🧠 На практике **90% запросов** сначала делают в консоли.

**40. Параметры запроса**

**Зачем нужны параметры**

Параметры:

- делают запрос универсальным

- защищают от SQL-инъекций

- улучшают производительность (кеш планов)

**Как объявляются параметры**

В тексте запроса:

ГДЕ

Дата \<= &Дата

В коде:

Запрос.УстановитьПараметр(\"Дата\", ДатаОтчета);

📌 Имена параметров **без &**.

**41. Что можно передавать в параметры**

Можно:

- даты

- числа

- строки

- ссылки

- массивы

- значения перечислений

❌ Нельзя:

- произвольный текст запроса

- имена таблиц / полей

🧠 Параметры --- это **значения**, а не структура запроса.

**42. Выполнение запроса**

**Базовый вариант**

Результат = Запрос.Выполнить();

📌 На этом этапе:

- запрос уходит на сервер

- выполняется в СУБД

- результат возвращается

**43. Получение выборки**

**Самый частый способ --- Выбрать()**

Выборка = Результат.Выбрать();

- возвращает курсор

- строки читаются по одной

- экономно по памяти

**Обход выборки**

ПОКА Выборка.Следующий() ЦИКЛ

// обработка строки

КОНЕЦЦИКЛА;

📌 Это **стандартный паттерн**.

**44. Доступ к полям выборки**

Поля доступны:

- по имени

- через точку

Выборка.Номенклатура

Выборка.Цена

⚠️ Имя поля = псевдоним из запроса.

**45. Выборка vs выгрузка в таблицу значений**

**Альтернатива --- Выгрузить()**

ТЗ = Результат.Выгрузить();

🧠 Разница:

  --------------------------------------
  **Метод**     **Когда использовать**
  ------------- ------------------------
  Выбрать()     большие данные

  Выгрузить()   маленькие данные
  --------------------------------------

📌 Выгрузить():

- загружает всё в память

- удобнее, но дороже

**46. Частая ошибка с Выгрузить() ⚠️**

❌ Выгружать:

- десятки тысяч строк

- «чтобы было удобнее»

📌 Итог:

- рост памяти

- тормоза

- падения на сервере

**47. Работа с пакетными запросами в коде**

При пакетном запросе:

Результат = Запрос.Выполнить();

➡️ возвращается **набор результатов**, а не один.

**Получение конкретного результата пакета**

Результат1 = Результат\[0\];

Результат2 = Результат\[1\];

📌 Нумерация:

- начинается с **0**

- соответствует порядку запросов в пакете

**48. Получение выборки из пакетного запроса**

Выборка = Результат\[0\].Выбрать();

🧠 Очень частая точка ошибки --- забывают индекс.

**49. Пакетные запросы + временные таблицы в коде**

Важно помнить:

- временные таблицы живут **только внутри запроса**

- из кода к ним **нет прямого доступа**

- код работает **только с результатами**

📌 ВТ --- это внутренняя кухня СУБД.

**50. Типовые ошибки при работе с запросами в коде**

⚠️ Не установлен параметр

⚠️ Ошибка имени параметра

⚠️ Несовпадение псевдонимов

⚠️ Использование Выгрузить() без нужды

⚠️ Ожидание одного результата вместо пакета

**51. Отладка запросов из кода**

**Лучший приём**

1️⃣ Скопировать текст запроса

2️⃣ Вставить в консоль запросов

3️⃣ Подставить параметры

4️⃣ Проверить результат

🧠 **Никогда не отлаживай запросы "вслепую" в коде.**

**52. Хороший стиль работы с запросами**

Рекомендации:

- запрос --- отдельный логический блок

- понятные имена параметров

- минимум логики в коде

- максимум логики в запросе

- комментарии для сложных мест

**53. Итог по работе с запросами в коде**

- объект Запрос --- центральный элемент

- параметры обязательны

- Выбрать() --- основной способ чтения

- Выгрузить() --- осторожно

- пакетные запросы требуют индексов

- ВТ скрыты от кода

**Пакетные запросы, временные таблицы и работа с запросами в коде --- итоги и паттерны**

**54. Типовые паттерны использования запросов в коде**

**Паттерн 1. «Запрос готовит данные --- код обрабатывает»**

**Идея:**

- вся выборка, фильтрация, агрегация --- в запросе

- в коде --- минимум логики

❌ Плохо:

- запрос «сырой»

- в коде куча условий и расчётов

✅ Хорошо:

- запрос возвращает уже нужный результат

- код только проходит по выборке

**55. Паттерн 2. «Один логический шаг --- один запрос пакета»**

Используй пакетные запросы так:

- шаг 1 --- подготовка данных (ВТ)

- шаг 2 --- уточнение / соединение

- шаг 3 --- финальный результат

🧠 Это делает:

- запрос читаемым

- логику прозрачной

- отладку простой

**56. Паттерн 3. «Временные таблицы вместо вложенных подзапросов»**

Если:

- подзапрос сложный

- используется несколько раз

- плохо читается

➡️ выноси его во временную таблицу.

📌 Код становится:

- короче

- понятнее

- легче для оптимизации

**57. Паттерн 4. «Один пакет --- одна бизнес-задача»**

Не стоит:

- лепить в пакет «всё подряд»

- мешать независимые запросы

📌 Пакетный запрос должен:

- решать **одну задачу**

- возвращать логически связанные результаты

**58. Типовые ошибки при работе с пакетными запросами ⚠️**

❌ Ожидать один результат, когда их несколько

❌ Перепутать порядок запросов

❌ Использовать ВТ до ПОМЕСТИТЬ

❌ Делать ВТ слишком большими

❌ Не удалять тяжёлые ВТ

❌ Делать пакет ради «красоты», а не пользы

**59. Типовые ошибки при работе с запросами в коде ⚠️**

❌ Не установить параметр

❌ Ошибка в имени параметра

❌ Использовать Выгрузить() без необходимости

❌ Читать объект вместо запроса

❌ Отлаживать запрос «на глаз»

📌 Эти ошибки --- самые частые причины багов и тормозов.

**60. Как проектировать запрос «правильно» (чек-лист)**

Перед тем как писать код, спроси себя:

1️⃣ Что я хочу получить на выходе?

2️⃣ Какие данные реально нужны?

3️⃣ Где лучше считать --- в запросе или коде?

4️⃣ Нужен ли пакет или хватит одного запроса?

5️⃣ Нужны ли временные таблицы?

6️⃣ Сколько строк вернётся?

7️⃣ Как это будет работать на больших объёмах?

🧠 Если на эти вопросы есть ответы --- запрос будет хорошим.

- нет магических чисел

**Виды обхода результата запроса в 1С**

**1. Что такое результат запроса**

После выполнения запроса:

Результат = Запрос.Выполнить();

мы получаем **результат запроса**, который:

- сам по себе **не данные**

- а контейнер, из которого можно получить данные **разными способами**

📌 Именно выбор способа обхода **влияет на память, скорость и архитектуру кода**.

**2. Основные способы обхода результата запроса**

В 1С существует **3 основных способа** работы с результатом запроса:

1️⃣ Через Выбрать() --- выборка

2️⃣ Через Выгрузить() --- таблица значений

3️⃣ Через Выбрать(ОбходРезультатаЗапроса.ПоГруппировкам) --- иерархический обход

Дополнительно:

- обход пакетных запросов

- обход с итогами

**3. Обход через Выбрать() (потоковый)**

**3.1 Как работает**

Выборка = Результат.Выбрать();

ПОКА Выборка.Следующий() ЦИКЛ

// обработка строки

КОНЕЦЦИКЛА;

🧠 Это **потоковый обход**:

- строки читаются по одной

- в память загружается минимум данных

- самый экономный способ

**3.2 Когда использовать**

✅ Используй Выбрать(), если:

- много строк

- данные обрабатываются последовательно

- не нужна сортировка/фильтрация в коде

- нужен максимальный перфоманс

**3.3 Ограничения**

❌ Нельзя:

- перейти к произвольной строке

- вернуться назад

- узнать количество строк без полного обхода

📌 Это **курсор**, а не коллекция.

**4. Обход через Выгрузить() (в память)**

**4.1 Как работает**

ТЗ = Результат.Выгрузить();

ДЛЯ КАЖДОГО Строка ИЗ ТЗ ЦИКЛ

// обработка

КОНЕЦЦИКЛА;

🧠 Все данные:

- загружаются в память

- доступны сразу

- можно обрабатывать как угодно

**4.2 Когда использовать**

✅ Используй Выгрузить(), если:

- данных мало

- нужно:

  - сортировать

  - фильтровать

  - группировать в коде

- нужна случайная навигация

**4.3 Когда нельзя использовать ⚠️**

❌ Если:

- десятки тысяч строк

- данные потенциально большие

- сервер с ограниченной памятью

📌 Частая причина утечек памяти.

**5. Иерархический обход по группировкам**

Используется, если в запросе есть:

- СГРУППИРОВАТЬ ПО

- ИТОГИ

- иерархическая структура результата

**5.1 Как выглядит в коде**

Выборка = Результат.Выбрать(

ОбходРезультатаЗапроса.ПоГруппировкам

);

**5.2 Как работает логически**

Результат превращается в дерево:

- группы

  - подгруппы

    - строки

📌 Ты управляешь уровнем вложенности.

**5.3 Пример структуры**

Контрагент

├─ Документ 1

├─ Документ 2

└─ ИТОГО

**6. Обход группировок в коде**

**Пример**

Выборка = Результат.Выбрать(

ОбходРезультатаЗапроса.ПоГруппировкам

);

ПОКА Выборка.Следующий() ЦИКЛ

ЕСЛИ Выборка.ЭтоГруппа() ТОГДА

// начало группы

ИНАЧЕ

// строка данных

КОНЕЦЕСЛИ;

КОНЕЦЦИКЛА;

**7. Работа с итогами при обходе**

Если в запросе есть ИТОГИ:

ЕСЛИ Выборка.ЭтоИтог() ТОГДА

// обработка итогов

КОНЕЦЕСЛИ;

📌 Итоги --- **отдельные строки**, а не флаги.

**8. Типичные ошибки при обходе результатов ⚠️**

❌ Использовать Выгрузить() по умолчанию

❌ Пытаться сортировать потоковую выборку

❌ Игнорировать ЭтоГруппа()

❌ Путать итоги с обычными строками

❌ Смешивать разные типы обхода

**9. Как выбрать правильный способ обхода**

**Быстрая таблица выбора**

  ------------------------------------------
  **Задача**                **Способ**
  ------------------------- ----------------
  Много строк               Выбрать()

  Мало строк                Выгрузить()

  Нужна иерархия            ПоГруппировкам

  Нужны итоги               ПоГруппировкам

  Нужна сортировка в коде   Выгрузить()
  ------------------------------------------

🧠 **Правило по умолчанию**:

Если не уверен ---

**используй Выбрать()**

А Выгрузить() --- **осознанный выбор**, а не привычка.
